# PostgreSQL authority in daemon startup: source audit

This audit is anchored to Bahia commit `bc0a616de72fe943deca2a8014d4c252d3ced25e` (before the relay-first remediation). Line numbers refer to that commit. The governing contract is [relay-canonical state](../architecture/intents-and-authority.md): SQL is an optional, rebuildable index; a SQL row cannot be an instruction to sign or publish an event. `TestNoAutomaticSQLToCanonicalPromotion` is deliberately a zero-baseline integration gate for the paths below. An unmodified base fails it.

## Health and non-promoting paths

| Source | Observed behavior and disposition |
|---|---|
| `internal/app/app.go:188,3080-3091` → `internal/db/db.go:17-47`, `internal/db/migrate.go:47+` | Optional DB connection happens synchronously in `New`: Ping has a 5-second bound, but schema migration uses the caller's background context. An available but slow/blocked database can delay HTTP startup. Bound or decouple optional connection/migration from core server startup; test slow as well as absent PG. |
| `internal/app/app.go:776` → `internal/app/db_recovery.go:32-69` | Database-recovery runner is registered non-required; it probes/migrates and asks for a process restart when SQL returns. It does not itself sign or publish, but a restart re-enters every boot path. Keep it non-required and ensure recovered SQL cannot reactivate promotion or disrupt core readiness. |
| `internal/app/app.go:1197`, `internal/adapters/nostr/projector_warmstart.go:51-145` | Projector history is `NewLocalEventRepository(localEventStore).Authored(servicePubkey)` and waits for first relay catch-up before comparing/re-publishing stale local records. This is the allowed relay+bbolt warm-up, not SQL promotion. |
| `internal/app/app.go:919,824-834`, `internal/adapters/nostr` bootstrapper | Bootstrap reads configured relays into the local event store; `bootstrap_ready` is based on relay catch-up, not PG. Identity/checkpoint/readiness status publications are bootstrap observables, not SQL-derived. |
| `internal/adapters/nostr/publish_delivery.go:797-841` | Normal outbox recovery discovers **local** pending entries and tracks per-relay acceptance. This is allowed, provided no boot path imports SQL pending rows into that outbox. |
| `internal/app/app.go:1843-1846` → `internal/adapters/nostr/legacy_ock_migration.go` | Legacy OCK migration uses relay/local projector history rather than SQL. It still re-signs on warm start, so its independent admission/idempotence properties need verification, but it is not a PostgreSQL authority path. |
| `internal/app/app.go:1305,2133,2192,2250,2704` | `RebuildIndex` hooks write PostgreSQL from retained canonical events. Direction is allowed, but serial post-warm-start execution must not delay relay-facing startup publications or core readiness. |

The regression matrix for acceptance is PostgreSQL absent, unavailable, empty, populated with redundant rows, slow, and divergent. In every case, a normal boot must have the same SQL-independent canonical publication count, an HTTP/core-readiness window bounded by relay catch-up rather than SQL work, and identical latest canonical coordinates from relays plus local bbolt/outbox. Static gates alone do not prove that matrix; the production Docker and exact-digest staging soak remain independent evidence requirements.
