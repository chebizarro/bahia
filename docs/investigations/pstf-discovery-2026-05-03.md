# Investigation: PSTF Discovery Product and Planning Map

## Summary
Bahia is a deployment and runtime control plane whose current product shape is relay-read-model-first, signer-first, and partly encrypted-route-driven. The strongest PSTF onboarding slices are the encrypted control plane, the core service-to-deployment flow, and signer-first operator adoption/direct-runtime flows; the main documentation risk is that older REST-centric docs lag the current control-plane implementation.

## Symptoms
- Need a grounded map of Bahia's product purpose, capabilities, planning docs, implementation areas, and test coverage.
- Need clear identification of stale or conflicting specs and candidate onboarding slices.

## Background / Prior Research
- Initial repo scan shows major surfaces in `web/src/routes`, `internal/controlplane`, `internal/api`, `internal/service`, `internal/domain`, and `test`.
- Existing docs appear concentrated under `docs/`, with investigations under `docs/investigations/` and control-plane guidance in `docs/control-planes.md`.

## Investigator Findings

### PSTF Discovery Map - 2026-05-03

#### Product purpose and authority ranking

**Observed product purpose.** Bahia is a Nostr-native deployment and runtime control plane: the README frames the core promise as tracking builds, deploying containers, detecting drift, recording to Nostr, rollback, and optional Soul Factory provisioning (`README.md:8-15`). The core domain model supports that purpose with build, artifact, deployment intent/run, runtime observation, and service state entities (`internal/domain/models.go:1-119`, `internal/domain/models.go:221-303`). Newer control-plane docs broaden the product from REST deployment registry to sidecar-first Nostr control plane, native MCP, narrowed REST compatibility, encrypted browser operations, adoption/import, direct-runtime actions, and LLM control-plane flows (`docs/control-planes.md:3-18`, `docs/control-planes.md:60-80`, `docs/control-planes.md:223-260`).

**Authority ranking for PSTF mapping.** Treat implementation contracts as highest authority: domain structs/status enums (`internal/domain/models.go:1-119`, `internal/domain/llm.go:1-198`, `internal/domain/soul.go:1-220`), runtime discovery (`internal/api/handlers/system.go:42-112`, `internal/api/handlers/system.go:211-248`, `internal/api/handlers/system.go:260-328`), router wiring (`internal/api/router/router.go:177-458`), and transport code (`internal/controlplane/encrypted_transport.go:14-31`, `internal/controlplane/encrypted_transport.go:217-260`, `internal/controlplane/operator_actions.go:124-260`). Among docs, `docs/control-planes.md` is the most current narrative because it matches the sidecar-first topology, 596x/696x/796x event contract, encrypted 5980/7980 flows, EOSE guidance, and 311xx deprecation (`docs/control-planes.md:3-18`, `docs/control-planes.md:82-139`, `docs/control-planes.md:223-260`, `docs/control-planes.md:288-300`).

#### Major product flows

1. **System discovery and feature gating.** A now-removed legacy HTTP discovery endpoint returned registries, Nostr relay topology, control-plane kind maps, runtime/OCI/blossom config, and feature flags (`internal/api/handlers/system.go:42-112`, `internal/api/handlers/system.go:211-248`). The web bootstrap path used that response to resolve browser relays, require `features.relay_read_models`, connect to Nostr, query read models until EOSE, then subscribe live (`web/src/lib/stores/controlplane.svelte.js:181-223`, `web/src/lib/stores/controlplane.svelte.js:524-580`). **observed_not_specified:** `docs/api.md` documented many REST resource routes but omitted that discovery surface even though it acted as a product-critical capability/topology contract (`docs/api.md:1-175`, `internal/api/router/router.go:177-179`).

2. **Relay read-model dashboard/state flow.** The browser read-model store maintains services, environments, states, LLM routes/states, artifacts, builds, deployment intents/runs, policies, workers, and activity from Nostr events (`web/src/lib/stores/controlplane.svelte.js:24-48`). It filters canonical Bahia events by the advertised service pubkey (`web/src/lib/stores/controlplane.svelte.js:210-223`), dedupes events and latest-wins replaceables (`web/src/lib/stores/controlplane.svelte.js:388-465`), uses EOSE bootstrap (`web/src/lib/stores/controlplane.svelte.js:558-580`), and subscribes live after bootstrap (`web/src/lib/stores/controlplane.svelte.js:502-522`).

3. **Public signer-first command flow.** Web writes for service/deployment/policy operations publish signed Nostr request events, require at least one relay OK acceptance, then await correlated result events by `#e` and service author (`web/src/lib/stores/public-controlplane.svelte.js:21-101`, `web/src/lib/nostr/controlplane-requests.js:74-100`, `web/src/lib/nostr/controlplane-requests.js:117-188`). This aligns with docs requiring publish + subscribe rather than polling (`docs/control-planes.md:166-186`, `docs/nostr-commands.md:1-5`, `docs/nostr-commands.md:139-147`).

4. **Encrypted request/result flow for sensitive domains.** Backend and frontend agree on request kind `5980`, result kind `7980`, routing tag `encrypted=bahia-encrypted-v1`, NIP-44 content envelopes, and correlated result tags (`internal/controlplane/encrypted_transport.go:14-47`, `internal/controlplane/encrypted_transport.go:108-157`, `web/src/lib/nostr/encrypted-controlplane.js:6-13`, `web/src/lib/nostr/encrypted-controlplane.js:103-131`, `web/src/lib/nostr/encrypted-controlplane.js:165-199`). Backend registration wires encrypted payments/orgs, service secrets/logs/signatures, and notifications into the encrypted transport (`internal/app/app.go:443-469`, `internal/controlplane/encrypted_domain_handlers.go:20-31`, `internal/controlplane/encrypted_domain_handlers.go:81-95`, `internal/controlplane/encrypted_route_handlers.go:19-27`, `internal/controlplane/encrypted_route_handlers.go:91-101`, `internal/controlplane/notification_encrypted_handlers.go:16-23`, `internal/controlplane/notification_encrypted_handlers.go:48-59`).

5. **Adoption/import and direct-runtime operator flow.** REST compatibility routes are feature-gated and operator-gated with dedicated rate limits (`internal/api/router/router.go:420-458`). The signer-first Nostr path validates pubkey authorization, rejects public `docker_host` material, publishes status/result replies, and maps scans/imports/actions to service-layer calls (`internal/controlplane/operator_actions.go:124-260`, `internal/controlplane/operator_actions.go:310-437`). Docs correctly state adoption and direct runtime are disabled by default, signer-first, pubkey-authorized, endpoint-ref oriented, and HTTP fallback is compatibility-only (`docs/adoption-production-rollout.md:7-18`, `docs/adoption-production-rollout.md:21-69`, `docs/adoption-production-rollout.md:128-144`).

6. **Soul Factory flow.** Soul Factory is Nostr-native: event kinds and lifecycle/resource-tier concepts are in the domain model (`internal/domain/soul.go:13-80`, `internal/domain/soul.go:111-175`, `internal/domain/soul.go:221-254`); the web store queries soul/template events from relays, subscribes to soul updates, tracks provisioning status/result events, and publishes lifecycle action events (`web/src/lib/stores/souls.svelte.js:1-70`, `web/src/lib/stores/souls.svelte.js:78-159`, `web/src/lib/stores/souls.svelte.js:173-304`, `web/src/lib/stores/souls.svelte.js:329-388`). **observed_not_specified:** there is no REST route or handler for `/souls`; router/handler searches for souls are empty, while `/souls` UI is relay-backed (`web/src/routes/souls/+page.svelte:1-43`).

#### Stale, conflicting, or incomplete docs

- **README is accurate for the original core but stale for current control planes.** It lists core deployment capabilities and current status (`README.md:8-15`, `README.md:60-80`) but omitted the relay sidecar, the former HTTP discovery contract, MCP, encrypted 5980/7980 request/results, adoption/import, direct-runtime actions, and LLM route control. Its doc index also omitted current control-plane/adoption/sidecar docs (`README.md:145-155`).
- **Architecture doc is REST/registry-centric and incomplete.** It describes a REST API and service layer for CRUD and deployments (`docs/architecture.md:17-31`) and includes OCI/Hive-CI sections (`docs/architecture.md:36-82`), but the source-of-truth table still says container images live in Harbor (`docs/architecture.md:130-136`) and it omits sidecar-first relay topology, encrypted request/results, adoption/direct runtime, and LLM control-plane behavior that current docs call primary (`docs/control-planes.md:3-18`, `docs/control-planes.md:60-80`).
- **Protocol compatibility doc conflicts with current control-plane docs.** It marks NIP-46 as stubbed in the quick matrix (`docs/protocol-compatibility.md:8-13`) but later says Signet client implements full NIP-46 while CLI `--nip46` is not implemented (`docs/protocol-compatibility.md:359-381`) and marks NIP-46 ✅ in the summary (`docs/protocol-compatibility.md:415-430`). It also presents 31100-31105 inbound commands as implemented (`docs/protocol-compatibility.md:132-143`, `docs/protocol-compatibility.md:415-430`) while current control-plane and Nostr-command docs say the 311xx bridge is deprecated/quarantined (`docs/control-planes.md:288-300`, `docs/nostr-commands.md:149-153`).
- **Nostr command docs lag adoption/encrypted families.** They document service/LLM 596x/696x/796x/read-model families and 311xx deprecation (`docs/nostr-commands.md:7-19`, `docs/nostr-commands.md:149-153`) but omit adoption `5978/5979/6978/7978/7979`, direct-runtime `6963`, and encrypted `5980/7980` that are specified in `docs/control-planes.md` (`docs/control-planes.md:82-139`, `docs/control-planes.md:223-260`). **specified_not_observed in docs.**
- **API docs omit several mounted surfaces.** `docs/api.md` covers services/environments/builds/artifacts/deployments/adoption/direct-runtime/OCI (`docs/api.md:35-169`) but omitted the former HTTP discovery surface (`internal/api/router/router.go:177-179`), `/mcp` and `/api/v1/mcp` (`internal/api/router/router.go:173-175`, `internal/api/router/router.go:412-414`), and workers/payments/policies/secrets/SBOM/signatures/notifications/LLM/orgs routes that are mounted conditionally in router (`internal/api/router/router.go:241-321`, `internal/api/router/router.go:358-390`, `internal/api/router/router.go:435-443`).
- **Web production plan is historical/mixed-authority.** It claims production-ready status, 100% endpoint coverage, and no notifications UI (`docs/WEB_APP_PRODUCTION_PLAN.md:1-61`), but current routes/stores include encrypted notifications UI (`web/src/routes/notifications/+page.svelte:1-20`, `web/src/lib/stores/notifications.svelte.js:1-23`). Treat it as historical unless reconciled.

#### Undocumented or under-documented behavior

- **Runtime discovery is a product contract, not merely metadata.** The web store loads `/system/info` before relay bootstrap and errors if relay read models are not advertised (`web/src/lib/stores/controlplane.svelte.js:524-560`); `SystemInfoResponse` includes features and kind maps (`internal/api/handlers/system.go:91-112`, `internal/api/handlers/system.go:260-328`). This should become its own PSTF feature contract.
- **The web app is now relay-read-model-first for shared state.** Compatibility exports such as `loadServices`, `loadEnvironments`, `loadDeploymentIntents`, and `loadWorkers` all call `bootstrapControlplane()` rather than REST list endpoints (`web/src/lib/stores/index.svelte.js:61-69`). That behavior is not obvious from README/API docs, which remain REST-centric (`README.md:104-119`, `docs/api.md:35-101`).
- **Additional public request kinds exist beyond older docs.** The JS kind map includes service/environment update/delete and policy/artifact request kinds 5981-5989 (`web/src/lib/nostr/client.js:14-48`) and public-controlplane helpers publish them (`web/src/lib/stores/public-controlplane.svelte.js:29-101`). These are not represented in `docs/control-planes.md` request table, which lists encrypted request kind 5980 but service requests only 5961-5968 (`docs/control-planes.md:82-104`). **observed_not_specified.**
- **Soul flows still contain timeout/polling-like completion logic.** Soul templates/souls use a `query()` helper with a timeout fallback (`web/src/lib/nostr/client.js:596-625`, `web/src/lib/nostr/client.js:717-735`), and provisioning tracking fails after a 120s interval without events (`web/src/lib/stores/souls.svelte.js:171-211`). That conflicts with the repo's Nostr guardrails when used as delivery/completion semantics; if kept, PSTF should record this as a protocol smell requiring product/architecture decision.
- **Reconnect backoff is correctly timer-based.** Reactor reconnect uses exponential backoff after subscription closure (`internal/controlplane/reactor.go:296-310`), which is allowed by guardrails and should not be confused with event polling.
- **Relay capability awareness exists in tests.** Relay info tests cover NIP support, AUTH-required flags, max limits/subscriptions, and uncached behavior (`internal/adapters/nostr/relay_info_test.go:17-122`), providing a foundation for NIP-11-related acceptance criteria.

#### Recommended PSTF onboarding slices

1. **Encrypted Control-Plane: notifications + encrypted result transport.** Scope: `/system/info` encrypted feature gate, browser relay separation, kind 5980/7980 envelope, publish OK handling, result correlation, backend auth/decrypt/error paths, and notification channel/log operations. Candidate evidence: docs contract (`docs/control-planes.md:223-280`), backend transport (`internal/controlplane/encrypted_transport.go:14-47`, `internal/controlplane/encrypted_transport.go:217-334`), backend handlers (`internal/controlplane/notification_encrypted_handlers.go:16-59`), frontend transport/store (`web/src/lib/nostr/encrypted-controlplane.js:72-259`, `web/src/lib/stores/notifications.svelte.js:20-136`), tests (`web/tests/unit/encrypted-controlplane.test.js:32-149`, `web/tests/unit/notifications-store.test.js:32-100`, `internal/controlplane/encrypted_transport_test.go:97-228`). Acceptance criteria should explicitly forbid sensitive payloads on public relays and require OK false/error propagation.

2. **Core deployment read/write path: service create to deployment intent/result.** Scope: system discovery → read-model bootstrap/EOSE → service create command → deployment intent → approval/result/read-model update → run logs/history. Candidate evidence: domain model (`internal/domain/models.go:103-119`, `internal/domain/models.go:233-303`), routes/handlers (`internal/api/handlers/services.go:24-64`, `internal/api/handlers/deployments.go:37-101`, `internal/api/router/router.go:196-211`, `internal/api/router/router.go:347-371`), public Nostr helpers (`web/src/lib/stores/public-controlplane.svelte.js:21-80`, `web/src/lib/nostr/controlplane-requests.js:74-188`), E2E (`web/tests/e2e/deployment-workflow-critical.spec.js:5-323`). Acceptance criteria should distinguish REST compatibility from canonical Nostr command/result semantics.

3. **Adoption/import and direct-runtime operator slice.** Scope: feature disabled-by-default, operator pubkey authorization, endpoint-ref-only signer-first requests, redaction, scan/import result status, direct-runtime deploy/restart/stop status/result, metrics/rate-limit behavior. Candidate evidence: rollout runbook (`docs/adoption-production-rollout.md:7-18`, `docs/adoption-production-rollout.md:21-69`, `docs/adoption-production-rollout.md:77-144`), REST handlers/routes (`internal/api/handlers/adoption.go:69-157`, `internal/api/router/router.go:420-458`), Nostr operator handlers (`internal/controlplane/operator_actions.go:124-260`, `internal/controlplane/operator_actions.go:310-437`), tests (`internal/api/handlers/adoption_handlers_test.go:54-220`, `internal/controlplane/reactor_operator_actions_test.go:83-260`). This slice is operationally important and has strong backend tests, but has no observed web UI route, so PSTF should treat it as CLI/API/operator behavior rather than browser behavior unless product decides otherwise.
